# Разбор PublishController

## Инструкция для кандидата

Проанализируй `app/Http/Controllers/PublishController.php` и опиши найденные проблемы.
Сколько их — реши сам. Для каждой проблемы заполни:

1. **Где:** строка или метод
2. **В чём суть:** что делается неправильно
3. **Последствие:** к чему это приводит
4. **Исправление:** как бы ты это переделал

## Пример формата (на постороннем коде, не из этого проекта)

### Проблема: отсутствие пагинации

**Где:** Метод `index()`, примерно строки 12–18.

**В чём суть:** Метод возвращает весь список сущностей без постраничной выборки.

**Последствие:** На большой таблице ответ и потребление памяти растут неограниченно; риск таймаута.

**Исправление:** Отдавать результат постранично (`paginate()`), возвращать метаданные страницы.

## Твой разбор

_Добавь столько блоков, сколько проблем нашёл._

### Проблема 1: Нет проверки прав доступа (IDOR issue)

**Где:** batch() method

**В чём суть:** любой пользователь может опубликовать чужие посты

**Последствие:** пользователь может изменить статус и содержимое постов, которые ему не принадлежат

**Исправление:** фильтровать post_ids по user_id на уровне запроса

### Проблема 2: N+1 запросы к БД

**Где:** batch() method

**В чём суть:** Вместо одного запроса с eager loading выполняется по несколько запросов на каждый элемент

**Последствие:** Влияет на производительность, риск таймаута при большом количестве данных

**Исправление:** Post::with(['user', 'comments'])->whereIn('id', $postIds)->get()

### Проблема 3: Нет валидации данных

**Где:** batch() method

**В чём суть:** параметры берутся из $request->input() без правил валидации. нет проверки типов, обязательности полей, допустимых значений status

**Последствие:** Некорректные или вредоносные данные могут дойти до бизнес-логики и БД. Ошибки проявляются как тихий пропуск (continue) вместо понятного ответа с описанием проблемы

**Исправление:** Вынести в FormRequest с правилами (post_ids — обязательный массив существующих ID, status — из фиксированного списка значений, body — опционально с ограничением длины).

### Проблема 4: published_at перезаписывается при повторном вызове

**Где:** batch() method, 'published_at' => now()

**В чём суть:** Если пост уже был опубликован, повторный вызов затирает исходную дату публикации текущим временем.

**Последствие:** Теряется реальная дата первой публикации

**Исправление:** 'published_at' => $post->published_at ?? now()


### Проблема 5: Publish-эндпоинт позволяет менять контент и статус

**Где:** Строки 'body' => $request->input('body', $post->body) и 'status' => $request->input('status', 'published')

**В чём суть:** Метод называется и позиционируется как публикация, но фактически разрешает менять содержимое и произвольный статус.

**Последствие:** Можно случайно или намеренно изменить контент поста через endpoint, не предназначенный для этого.

**Исправление:** Убрать body из этого эндпоинта; для publish фиксировать status = published.

### Проблема 6: Пропущенные посты никак не объясняются

**Где:** оба `continue`

**В чём суть:** Любой пропуск (несуществующий ID, короткий reason) выглядит для клиента одинаково — просто не попадает в результат

**Последствие:** User получает published: 3 вместо 5 и не понимает, что случилось с остальными

**Исправление:** Валидировать publish_reason заранее (min:10), а по каждому ID возвращать явный статус — обработан/пропущен и почему

### Проблема 7: report() загружает всё без pagination

**Где:** Post::all()

**В чём суть:** Загружаются все посты и все комментарии каждого поста целиком, без лимита

**Последствие:** Риск таймаута

**Исправление:** paginate() вместо all(), и withCount('comments') вместо загрузки самих комментариев, если нужен только счётчик

### Проблема 8: strlen() вместо mb_strlen()

**Где:** $score = $commentCount * 10 + strlen($post->body);

**В чём суть:** strlen() считает байты, не символы. Для не-латинского текста (русский, армянский, emoji) результат сильно отличается от реальной длины текста.

**Последствие:** Score некорректен и непредсказуемо зависит от языка контента.

**Исправление:** mb_strlen($post->body)

---

**Важно:** мы оцениваем твоё понимание, а не длину списка. Лучше меньше проблем, но разобранных по сути, чем много формальных строк.
